# 仕組み

動画再生専用の 3DS アプリ (ROM 本体) と、それを CIA にする生成ツールの設計。

```
template/<名前>/  ──►  生成ツール (tool/mkcia)  ──►  <名前>.cia
 動画/画像/音声/meta.json     検証 → エンコード → banner/SMDH → romfs → RSF → makerom
                                          │
                  ROM 本体 (prebuilt/mediaplayer.elf、全テンプレート共通) ─┘
```

ROM 本体は 1 本で、テンプレートごとの違いは全て romfs の中身 (`video.mp4` / `bottom.png` / `config.json`) に入る。

## ROM 本体 (`rom/`)

devkitARM + libctru + citro2d/citro3d。ffmpeg は H.264 / AAC / MOV だけの最小構成を自前でクロスビルドして静的リンク。

### romfs

| ファイル | 内容 |
|---|---|
| `video.mp4` | H.264 Baseline + AAC-LC。生成ツールが 3DS 向けに再エンコード済み。幅・高さは 8 の倍数で 512x256 以下 |
| `bottom.png` | 下画面 (320x240) に表示する静止画 1 枚 |
| `config.json` | `{"loop": bool, "volume": 0.0-1.0, "deblock": bool}` |

`config.json` は平らな JSON として最小限のスキャナで読む。

### 再生

- **上画面**: ffmpeg でデコード → Y2R (YUV→RGB のハードウェア変換) の出力を、PICA200 のテクスチャ形式 (8x8 ブロックの Z-order)
  のまま直接テクスチャメモリへ書く → citro2d で描画。動画が上画面より小さければ、アスペクト比を保って全画面に拡大する。
- **下画面**: `bottom.png` を libpng で読み、生のフレームバッファ (BGR8) へ直接書く。終了時のフェードアウト用に複製を持つ。
- **音声**: swresample で 32bit float planar → 16bit ステレオに変換し、ndsp の波形バッファ (48 個) に積む。
- **同期**: 音声の再生位置 (再生中の波形バッファの先頭位置 + バッファ内の再生位置) を基準時計とする。
  映像は「基準時計に追いついた最新のフレーム」を表示し、それより古いフレームは捨てる (遅れたらスキップ)。
  まだ時刻になっていないフレームは待つ (進みすぎたら待機)。
- **スレッド**: デコードは別スレッド。New 3DS はアプリ用の追加コア (2)、旧3DS はアプリコア (0) の低優先度スレッド
  (メインスレッドはほぼ待機なので、残りの CPU をデコードが使う)。旧3DS のシステムコア (1) は CPU 時間の 30% までしか使えず
  間に合わないので使わない。デコード済みフレームは 12 枚のキューでメインへ渡す。
- **デブロッキング**: 既定ではデコーダのデブロッキングフィルタを省く (`skip_loop_filter`)。エンコード側もデブロック無しで作るので
  ドリフトしない。`config.json` の `deblock` で有効にできるが、負荷の割に画質の改善が小さいので、どのプリセットも無効。
- **終了**: `loop` が false の動画は、映像・音声とも再生し終えたら、約 1 秒で上下画面を黒くフェードアウトして終了する
  (上画面は黒の矩形のアルファを上げ、下画面は複製を暗くして書き戻す)。
- **音声が使えない場合**: DSP ファームウェアが無く `ndspInit` が失敗したら、音声ストリームを捨てて映像だけ再生する。
- **スタック**: メインスレッドのスタックは 256KB (`__stacksize__`)。libctru 既定の 32KB は H.264 デコードで溢れる。
  CIA にしたときは RSF の `StackSize` が効く。

### デバッグビルド

`-DDEBUG_LOG` でビルドすると、SD カード直下の `mediaplayer.log` に進行状況・ffmpeg のログ・デコード時間を書き、
`sdmc:/test_video.mp4` と `sdmc:/test_config.json` があれば romfs の代わりに使う (設定の比較測定用)。

## 生成ツール (`tool/mkcia`)

標準ライブラリだけの Python。処理ごとに独立した関数に分けてあり、CLI も GUI も同じ関数を呼ぶ。

| モジュール | 役割 |
|---|---|
| `validate.py` | 入力・出力先・ELF・外部ツールの事前検証 (重い処理の前にまとめて) |
| `meta.py` | `meta.json` の読み込みと検証 (型・長さ・範囲) |
| `video.py` | プリセットと、ffmpeg による動画の事前エンコード |
| `extract.py` | `icon` / `bottom` が無いとき、動画の埋め込み画像 → 指定秒数のフレームから元画像を作る |
| `assets.py` | アイコン (48x48)・バナー (256x128)・下画面 (320x240)・バナー音 (WAV 3 秒以内。無ければ既定のチャイム) の整形 |
| `banner.py` | bannertool で SMDH / banner を作る |
| `romfs.py` | romfs ディレクトリの組み立てと 3dstool での `romfs.bin` |
| `cia.py` | RSF の生成と makerom での CIA 化 |
| `pipeline.py` | 上記を順に呼ぶ。引数 > meta.json > 既定、の優先順位の解決もここ |
| `proc.py` | 外部コマンドの実行 (中止可能、ツールの探索) |
| `gui_model.py` / `gui.py` | GUI のロジック (Tk 非依存) / 画面 (Tkinter) |

### エンコード

3DS の CPU (ARM11 268MHz) のソフトウェアデコードで間に合うよう、プリセットで固定する。

- H.264 Baseline (CAVLC)、B フレーム無し、参照 1、キーフレーム間隔は 2 秒、デブロック無し、`-movflags +faststart`。
- 解像度は 8 の倍数。上画面 (400x240) より小さい場合は ROM が拡大する。アスペクト比は保ち、余白は黒。
  画素が正方形でない動画 (SAR≠1) は、先に表示上の幅へ直してからフィットする。
- fps は元動画がプリセットより低ければ元に合わせる (増やさない)。
- 音声は AAC-LC、32kHz、ステレオ。
- 画質を左右するのはビットレート。解像度を上げるコストは小さい (旧3DS で +5〜13%)。デブロッキングは +24〜31% の割に改善が小さい。

### CIA (RSF)

CIA の権限設定 (RSF) は、**エミュレータでは検査されないが実機では必須**。足りないと実機でだけ起動直後に落ちる。
`cia.py` の RSF は、実機で動いている homebrew の CIA と ExHeader を比較して合わせてある。

- `SystemCallAccess` (使えるシステムコール)、`MemoryMapping` (VRAM)、`IORegisterMapping` (DSP)、
  `FileSystemAccess` (SD の読み書き)、`ServiceAccessControl` (サービス一覧)、`Logo: Nintendo`。
- `makerom -desc app:N` は使わない (テンプレートがサービス一覧と SVC 制限を上書きして、実機で起動しなくなる)。
- 製品名 (NCCH の内部名) は ASCII 7 文字まで。非 ASCII は落として、残らなければ `MPLAYER`。ホームメニューの名前は SMDH 側。
- タイトルID のユニークID (`下位32bit >> 8`) は 20bit まで (makerom の上限)。

### 失敗しても壊さない

出力は一時ファイルに作ってから置き換える。中止・失敗・Ctrl+C のどれでも、中間ファイルと一時ファイルを残さず、既存の出力は変わらない。

## 性能の目安 (旧3DS 相当のエミュレータで測定)

実機 (旧3DS) で滑らかだった `light` を基準に、デコード時間 (ms/フレーム。20fps の予算は 50ms) を比べた結果。

| 設定 | ms/フレーム | `light` 比 |
|---|---|---|
| 320x192 / 250 kbps (`light`) | 42.8 | — |
| 360x216 / 400 kbps (`medium`) | 45.1 | +5% |
| 400x240 / 400 kbps (`high`) | 48.4 | +13% |
| 400x240 / 400 kbps + デブロック | 56.0 | +31% |

エミュレータの時間と実機の時間は一致しないので、「実機で滑らかだった設定との相対比較」としてのみ使える。
